# Historical Snapshot Views

The history diff response already contains complete from/to snapshots. Add a separate content-view segmented control (diff, reading, source); keep parallel/unified specific to diff. Reading/source display the selected snapshot (diff.from) or current snapshot (diff.to when selected current); label its exact hash/title. Source is escaped React preformatted text with original whitespace. Reading mounts a read-only Tiptap instance keyed by project/document/hash (and recreates the editor if content changes), using createMarkdownParsingExtensions and DocumentMention from the existing document schema, with no onUpdate/save/store/registry integration. Existing document image path resolution and section-media rendering stay available.

The parent gates every view through the existing SWR loading/error state; refresh hides cached snapshots while validating. Late/stale results cannot supply a preview for another response identity. Existing restore always targets selectedHash, remains disabled for current/dirty/conflict/loading/error, and retains frozen reviewedVersion. Viewing does not hydrate the store or serialize Markdown. This intentionally adds full historical reading/source inspection, not official reading-mode diff highlighting or arbitrary version comparison. Those gaps remain visible.
