# TASK-031 素材标签、备注、评分

来源：REQ-012 / TASK-030，2026-10-14 CURRENT-HANDOFF 与 DEC-023 持续实施授权。

## 目标与现状

素材导入后可以保存标签、备注、评分，并按标签/备注搜索，重开后保留。实际素材库使用 media-assets 与 selected-generation-assets 派生合并，不使用项目目录的 project-assets。现有 assets 表已有尺寸、时长、封面、存储状态及项目 ID；project_reference_assets 的 folderId 属于文档目录，不能直接冒充素材库文件夹。官方 30/37 截图仅展示空态，没有详情编辑的已知尺寸。

## 范围

- 物理媒体素材的标签、备注、0–5评分持久化，已有上传/重命名兼容。
- 详情真实编辑、保存、取消、清空；失败保留草稿并显示错误。
- 名称/标签/备注搜索；选入资源匹配物理媒体时共享元数据，无物理媒体的选入资源保持只读。
- 全局与项目更新 API 只能修改自身 scope；项目列表仍保留可见全局素材的兼容行为，全局素材编辑使用其实际 scope。
- 不移动文件，内容 URL、ID、路径、hash、引用不受元数据修改影响。

## 验收

1. SQLite 旧 schema 增量迁移默认空标签/备注/0评分；保存后关闭并重开 DB 可读，清空可持久化。
2. 省略字段保持原值，非法评分/类型/超限标签与备注返回400，跨scope返回404且零写入；内部故障返回500。
3. UI 保存、取消、失败草稿、切换素材、标签/备注搜索测试通过；浏览器导入专用文件，保存、取消、刷新、重开与API/文件hash核对。
4. 前端 lint/format/build/相关测试，后端完整 check/test/race/build 退出0；按界面、交互、功能分别记录。

## 边界与后续

测试 workspace 独立，保留既有数据与未提交变更。不登录、不生成、不提交Git。文件夹、目录扫描、项目整页官方布局、全局scope页面、NLE分别由后续子项承担，本项不宣称整张截图对齐。TASK-010继续待评审。
