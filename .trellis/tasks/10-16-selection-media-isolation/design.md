# Design

The workflow hydration silently ignores foreign media and proceeds to GenerationTaskService. Validate in that shared service under its current mutex, using the existing media repository read through GenerationTaskRepository (same DB, no second connection or service dependency). Reuse mediaAssetMatchesGenerationProject; missing/foreign sources share a package-local error mapped to404. Validate an explicit ID/URL-derived ID before task mutation, and the resolved task asset before marking it selected. Deselect validates its final hydrated source before row deletion. Preserve requests with no media identity for the existing task-resolution path.

Files: generation_task_repo.go (delegate existing media lookup), generation_tasks_service.go (pre-write validation), generation_runtime_tasks.go (status mapping), generation_tasks_service_test.go (regressions), backend error spec (contract). Hydration remains metadata enrichment; the write service owns enforcement. No claim of transaction isolation against concurrent library deletion or all unrelated DB write failures.

Actual global roundtrip exposed another part of the same direct-source cancellation contract: select hydrates a missing title but deselect did not, producing different selection identities. Reuse the same metadata enrichment before both branches. The same/global regression now uses the actual wired media service and omitted title, and fails before this adjustment. Explicit request titles retain their current identity behavior. A separate observed global downloadPath default-root projection is recorded for the next independent item; no access to that path is needed.
